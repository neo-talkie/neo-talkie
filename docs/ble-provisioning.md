# BLE 配网通路验证

## 0.2.3 手机配置与后台管理

手台名称固定为 `NeoTalkie-XXXX`。首次进入「手机配置」时生成四位十六进制编号并保存。助手优先显示手台认证回包的 `deviceName`，旧固件沿用 BLE 广播名。

1. 首次绑定或配网时，在手台打开「手机配置」，手机通过 BLE 扫描对应编号。核对两端确认码后在手台按 MENU，授权该手机通过同一 Wi-Fi 后台管理。需要换网时选择「配置 Wi-Fi」。
2. 旧绑定升级默认关闭后台管理。在「手机配置」按上下键选择「开启后台管理？」再按 MENU。这里也可以关闭后台管理或解除绑定。关闭后可以在配置页通过 BLE 建立临时管理连接。
3. 启用后台管理后，在任何页面点亮手台，打开助手即可自动重连最近使用的已绑定手台。助手先尝试上次的 Wi-Fi 地址，失败后从 BLE 广播读取当前 IPv4，再以原有绑定凭证认证。手台熄屏会停止广播、关闭后台管理端口并清除会话。助手首页会间歇重试，点亮手台即可恢复。手机与手台须在同一 Wi-Fi，微信需要本地网络权限，自动发现另需蓝牙权限。仍可手动输入地址或进入配网。
4. 在设备页编辑模型、密钥和 1–3 个频道，选择活动频道后保存。密钥留空保留原值。手台保存后，进行中的对讲继续使用已有配置。记录页可拉取最近 100 条文字问答及实际用量。对讲 APK 未安装或接口不兼容时，仍可连接设备和配网。

### 传输与会话

首次 BLE 授权沿用 0x15 绑定校验和加密凭据模式 2/3。在配置页内，现有客户端可用当次 BLE 秘密访问 Wi-Fi TCP 38671。页面退出或超时会关闭这个临时端口。后台授权独立使用 TCP 38672，仅绑定当前 Wi-Fi IPv4。后台服务订阅系统网络变化，被动等待请求；断网、换址、撤销授权时关闭旧会话。

亮屏发现使用不可连接的低功耗 BLE 广播。广告中只有一个自定义 128 位服务 UUID，格式为 `7d92e3b1-6f41-4c10-8101-XXXXaabbccdd`。XXXX 是手台编号，末八位是按网络字节序编码的 IPv4。例如 `CAFEc0a80109` 表示 NeoTalkie-CAFE 位于 192.168.1.9。单个广播包即可读取。助手从 `advertisServiceUUIDs` 匹配所选手台，验证绑定后才保存新地址。显式配网窗口优先使用原有可连接广播和 GATT。手台仅在有 Wi-Fi 地址、已绑定且已启用管理时广播，息屏时释放广播而保留系统蓝牙供音频使用。

后台会话使用三个 HTTP POST。所有握手值均为小写十六进制，手机随机数和手台随机数各 32 字节。HMAC-SHA256 的键为 BLE 已建立的 32 字节绑定凭证，输入是 ASCII 文本 `lan-v1/<角色>/<手机随机数>/<手台随机数>`。

| 路径 | 请求和结果 |
| --- | --- |
| `/hello` | 手机提交新的随机数；手台返回新的随机数、一个空格和角色 `radio` 的证明。 |
| `/session` | 手机核验手台后提交角色 `phone` 的证明。手台验证成功后消费一次性挑战，将角色 `session` 的 HMAC 输出作为 AES-256-GCM 会话密钥。挑战有效期 30 秒，管理会话空闲 5 分钟清除。 |
| `/manage` | 沿用递增序号和请求、响应各自的 GCM nonce。加密载荷包含 `app`、`api`、`op`、`data`。设备目录为 `device/info`，语音对讲按 `com.neotalkie.talk` 路由，接口版本为 1。 |

助手退到后台会释放当前会话，重新打开时可直接经 LAN 认证。请求结果不确定时，写配置和试听都不会自动重放。版本冲突时重新读取，由用户核对后提交。

## 历史协议与互通测试

0.1.2 首先验证手机与手台的 BLE 双向通信。桌面负责 GATT，小程序负责扫描、连接、分包发送与校验回执。当前只允许固定测试数据，不接收 Wi-Fi 密码，不修改网络，不保存收到的内容，不要求云端服务。0.1.2 的实际 Wi-Fi 配网未实现；0.2.0 的新增流程见本文后半部分。

## 现场步骤

1. 在手台桌面选择第四项「手机配网」，记住屏幕上的 `NeoTalkie-XXXX`。
2. iPhone 开启蓝牙，使用当前版本微信预览码打开设备助手，并允许微信使用蓝牙。若曾拒绝，在 iOS 设置的隐私与安全性 → 蓝牙中允许微信。
3. 在小程序蓝牙页扫描，选择编号与手台一致的设备，点击连接并测试。扫描最长 12 秒，可在发现后立即连接。
4. 小程序显示「蓝牙收发验证通过」，手台显示「验证通过」。仅扫描到名称不算通过；名称也不构成设备身份认证。
5. 手台退出此页、转到后台或五分钟到期，关闭本轮 GATT 和广播，恢复进入前的蓝牙名称及开关状态。到期后 MENU 可以重试。小程序离开页面会停止扫描、断开连接并关闭蓝牙适配器会话。

真实 iPhone 的授权提示、发现、连接、分包与回执必须现场验收。离线测试和开发工具编译不能替代真机验收。广播启动日志仅证明手台可广播，不能证明手机已连接。

## 临时验证协议

- Service UUID：`641f2000-cf44-4c44-9121-b0219fd08011`。
- Characteristic UUID：`641f2001-cf44-4c44-9121-b0219fd08011`，READ / WRITE（有响应）。初始读取 `NT1:READY`。
- 固定 UTF-8 数据：`NeoTalkie|测试网络_日本語_é|BLE`。
- BEGIN：`01 lengthHi lengthLo nonce[4]`，大端长度和 4 字节请求编号。
- DATA：`02 sequence payload[1..18]`，序号从 0 开始；每次 write 不超过 20 字节，按回调依次发送。
- 接收限长为固定样本长度，15 秒内完成。先完整组装字节再比较样本，允许一个多字节字符跨包。拒绝乱序、超长、错误内容和 prepare write。
- 最终 READ 返回 `NT1:OK:<8位小写十六进制编号>:<字节数>`。手机必须读取真实特征值事件并核对整个回执，不能只凭 write 成功显示通过。
- 请求编号只用于关联回执，不是密码或安全认证。此验证协议不能承载真实凭据，也不能直接升级为无鉴权的 Wi-Fi 配置接口。

# 实际 Wi-Fi 配网（0.2.1）

桌面 APK 新增受物理授权约束的 Wi-Fi 配置特征。原有固定数据测试保留在独立特征中，不能下发密码。微信设备助手增加连接配网、确认码、网络输入、取消与最终结果。

## 使用

1. 更新两个 APK 和设备助手预览到 0.2.1，手台桌面进入「手机配网」。
2. 手机扫描并选择同编号设备，点击「连接并配网」。
3. 核对手机与手台显示的 12 位十六进制确认码；完全一致时在手台按 MENU 授权。
4. 在手机填写 Wi-Fi 名称和密码，按需选择无密码或隐藏网络，然后点击「确认码一致，开始配网」。
5. 最长约 45 秒等待连接结果。成功要求目标网络已关联并取得非零 IPv4 地址，且系统保存配置成功；小程序展示 IP。此结果不代表已验证互联网或语音服务。

支持 Android 5.1 上的 WPA/WPA2 个人网络及开放网络；测试设备请使用 2.4GHz 网络。SSID 按 UTF-8 限制 1–32 字节；WPA 密码为 8–63 个可打印 ASCII 字符，不支持企业 EAP、WPA3-only 或 64 位十六进制 PSK。

关闭小程序配网页、断开 BLE、手台退出配网页或五分钟到期，都会取消尚未完成的连接尝试。失败或取消时删除本轮新建配置、恢复其他网络的自动连接资格，并在目标与原网络不同时尝试重连原网络。成功后保留系统配置。

**更新同名已保存网络会替换其密码。** Android 返回的旧密码是掩码，应用无法在失败后恢复它；小程序提交前明确提示这一限制。恢复原连接是尽力操作，不能保证原热点仍可用。应用不会读取、记录或上传系统已保存的密码。

## 授权与凭据保护

每次 BLE 连接单独生成 RSA-2048 密钥和 16 字节随机挑战。手机读取 256 字节模数（指数固定 65537）和挑战，手机预先生成 32 字节结果鉴别密钥，将其 SHA-256 承诺值分两包发送给手台。两端对「272 字节设备公钥材料 + 32 字节手机承诺值」计算 SHA-256，取前 48 位显示为两组各 6 位十六进制确认码。物理授权同时绑定设备和发起手机；设备解密后必须校验鉴别密钥的 SHA-256 与已确认承诺值一致，避免第三方替换密文配置。操作者必须核对两端代码；设备在本次连接收到物理 MENU 前拒绝凭据传输。名称仅用于发现，确认码不等同于厂商证书身份。


凭据采用 RSA-OAEP 加密。明文含协议版本、设备挑战、结果鉴别密钥、字段长度、网络类型/隐藏标志及 SSID/密码。设备仅接受一次、固定 256 字节密文，验证挑战、手机承诺值、长度、UTF-8 和密码范围；连接关闭后销毁会话引用。应用不写凭据文件、不打密码日志；只有成功配置所需的 Android 系统 Wi-Fi 保存。Java/JavaScript 的不可变字符串不能保证立即擦除，内存引用在使用后释放，字节数组尽力清零。

返回结果使用 HMAC-SHA256 的前 96 位验证，覆盖状态、手机轮询编号和 IP。手机拒绝错误 MAC、错误编号和零 IP 的成功回执。结果鉴别密钥通过 RSA 密文传入，不以明文广播。

## 配网 GATT 帧

配网特征为 `641f2002-cf44-4c44-9121-b0219fd08011`，支持 READ/WRITE，每帧最多 20 字节。


| 操作 | 写入 | 读取/行为 |
| --- | --- | --- |
| 公钥分段 | `10 page` | `10 page 10 data[17]`，16 页共 272 字节；生成中读 `7f` |
| 手机承诺 | `14 sequence data[1..18]` | 0、1 两包合计 32 字节，仅在未授权时接收一次；完成后显示确认码 |
| 状态轮询 | `11 counterHi counterLo` | 20 字节：`11 state counter[2] IPv4[4] MAC[12]`；鉴别密钥建立前 MAC 为零 |
| 开始凭据 | `12 01 00` | 必须已按 MENU 授权，进入接收态 |
| 密文分包 | `13 sequence data[1..18]` | 从 0 开始顺序累计 256 字节，15 秒内完成，否则拒绝 |

状态：1 等待物理授权、2 已授权、3 接收密文、4 连接中、5 已连接并保存、6 认证失败、7 超时、8 取消、9 系统错误、10 保存失败、11 配置无效。连接结果通过带 MAC 的状态包返回。手机只在状态 5、MAC/轮询编号正确且 IP 非零时显示成功。

## 验证边界

离线测试覆盖 Java 与实际小程序加密模块的密文互通、物理确认前拒绝、手机绑定与配置替换拒绝、一次性提交、挑战不匹配、乱序、篡改结果、旧编号拒绝，以及完整手机状态轮询。测试只使用虚构网络信息，绝不调用 Wi-Fi 或外部服务。真实手机与 Android 5.1 的首次配置、错误密码、取消、重启保留须单独在操作者现场验收。

对讲配置的每个频道返回 `replySeconds`（30、60 或 120 秒），新频道和原有无此字段的频道默认 30 秒。旧客户端省略字段时保留该频道已保存的时长。问答记录可携带 `topic` 字符串，未生成主题或旧记录可为空或缺省。

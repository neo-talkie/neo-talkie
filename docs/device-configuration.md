# 手台配置服务与子应用的架构约定

本约定用于 0.2.3 固件与设备助手。首个验收场景是：手台正在对讲，已绑定的手机此时才打开助手，也能在同一 Wi-Fi 下读取已完成的问答、保存新的活动频道。整个过程无需手台退出对讲，正在进行的语音轮次继续使用开始时的配置。

## 两个 APK，统一的管理入口

沿用现有包名和签名。桌面 APK 同时是手台配置 App，负责使设备入网、让用户选择谁可以管理设备，以及为所有子应用提供一个局域网管理入口。子应用决定自己的配置含义和落盘格式。新增应用时，在手台配置 App 登记其本机接口，在需要支持它的管理界面中接入专用页面。手机始终连接同一个服务。

| 模块 | 负责的工作 | 持有的数据 |
| --- | --- | --- |
| 手台配置 App（`com.neotalkie.launcher`） | HOME、系统设置入口、BLE 配网与首次授权、Wi-Fi 管理服务。列出已接入应用，鉴权后把操作交给目标应用。 | 手机绑定凭证、后台管理是否启用。Wi-Fi 凭据交给 Android 系统保存。 |
| 语音对讲 App（`com.neotalkie.talk`） | PTT、语音处理、频道和上下文。声明配置项，校验并保存配置，提供记录查询与试听。 | 私有 `files/config.json` 是对讲配置的唯一持久化来源。最近 100 条文字问答及实际用量保存在对讲私有数据库。 |
| 微信助手及后续管理界面 | 展示设备和子应用表单，提交修改、显示保存结果，按需读取记录。 | 设备名沿用手台广播的 `NeoTalkie-XXXX`，四位十六进制编号由配置 App 首次生成并保存。已认证的设备信息通过只读字段 `deviceName` 返回同一名称。手机可记住设备、绑定凭证和上次地址。密钥输入只用于本次提交，读取只显示设置状态。 |

手台配置 App 可以排布专用页面，子应用也可以有自己的手台设置界面。两种入口都使用该子应用的同一套校验和保存逻辑。对讲侧只开放签名权限保护的本机接口，外部客户端只能经配置 App 管理。这样无需共用 UID、开放私有目录或复制密钥文件。

## 子应用如何接入

**管理界面默认按应用定制。** 手台或微信助手可按应用标识直接打开手写页面。每个应用可以有一张或多张表单，分别设计字段、控件、布局、操作顺序和反馈。页面可以直接依赖该应用的配置接口。简单字段可按需复用控件或列成清单，接入无需通用表单 schema、描述文件或动态渲染器。

例如，语音对讲可以把“模型与密钥”和“频道管理”分成两张表单，在频道编辑页直接试听音色。以后若接入电脑对讲，可以用一张专用表单完成它的配置。两者共用同一管理连接，各自决定用户怎样操作。

1. **配置 App 负责接入和转发。** 在 `ManagedApp` 中显式登记应用标识、接口版本、受签名权限保护的本机 Provider 及允许的读写操作。客户端通过已认证的会话指定应用和操作。某个应用缺失或接口版本不兼容时，仅该应用的管理入口提示不可用。
2. **子应用与专用页面约定数据和操作。** 以语音对讲为例，页面通过配置 App 调用 `info` 读取脱敏配置、调用 `save` 保存，也可显式请求试听。两张表单可以使用同一套读写接口；字段如何分组显示由页面决定。
3. **子应用校验并保存。** 对讲以配置数据的 `version` 检查并发修改，校验通过后原子写入自己的文件，再返回新版本和脱敏结果。版本冲突时页面重新读取，让操作者核对后提交。升级时由子应用解释旧格式、补齐默认值并保留已有配置和密钥。

下表是语音对讲专用页面的设计示例。配置键和校验规则归对讲应用所有。

| 配置键 | 编辑方式与语义 |
| --- | --- |
| `model` | 文本框，填写模型或 endpoint ID。 |
| `voiceApiKey`、`arkApiKey` | 密码框。读取返回 `hasVoice`、`hasArk`；留空保存时保留原密钥。 |
| `channels` | 1–3 个频道，使用稳定 ID。专用编辑器维护名称、音色、提示词及上下文时长，时长可选 0、3、5、15 分钟。 |
| `channels[].replySeconds` | 每个频道的回答播报上限，可选 30、60、120 秒，默认 30 秒。旧客户端保存时，手台按频道 ID 保留已有时长。 |
| `activeChannelId` | 单选，必须引用本次提交中的一个频道。 |

对讲首页下侧键显示活动频道名称，每按一次按配置列表顺序前进，末项回到首项。单频道保留原选择和上下文。手台切换与手机保存共用同一配置版本和原子写入，手机重新读取即可看到新选择。正在进行的轮次按原频道完成并记账，下一轮开始使用新频道的音色、提示词和独立的新上下文。

手机保存成功后，前台对讲页重新读取频道名称和配置。正在进行的轮次沿用开始时的配置，下一次按下 PTT 使用最新设置。记录查询是只读分页操作，试听是显式业务动作，两者均由对讲执行。

## 配网窗口与 Wi-Fi 后台服务

0.2.2 中，`BleSetupActivity.onPause()` 调用 `end()`，同时释放 GATT 和 `ManagementEndpoint`。小程序退到后台也会清除管理会话，再次连接依赖前台 BLE 握手。这解释了为什么一切到对讲就无法拉取。只延长配置页的五分钟窗口，仍解决不了手机稍后打开时的重连。

0.2.3 由配置页持有 BLE 配网和兼容用的临时连接，由配置 APK 内的 ManagementService 持有后台局域网监听与短期会话。生命周期按以下事件处理。

| 事件 | 配置 App 的行为 |
| --- | --- |
| 首次绑定、更换手机或配网 | 操作者打开「手机配置」，核对确认码并在手台授权。保留未联网也可配网的能力。授权时明确告知已绑定手机可在同一 Wi-Fi 后台管理，并提供关闭入口。现存绑定升级后须在手台明确启用后台管理。 |
| 页面退出、超时或切到对讲 | 停止前台 BLE 广播、释放 GATT、取消未完成的配网。已授权且亮屏时，后台服务恢复低功耗发现广播并监听当前 Wi-Fi 地址。 |
| 手机稍后打开或会话过期 | 手机可先尝试上次地址，以绑定凭证在 LAN 上重新双向认证，建立新的短期加密会话。地址已变时，手机从手台 BLE 广播读取新地址并以原绑定认证，也可手动输入 IP。 |
| 熄屏、再次亮屏 | 熄屏停止发现广播、关闭后台监听和已有会话。亮屏时按当前 Wi-Fi 和绑定恢复，适用于任意应用。 |
| 断网、Wi-Fi 地址变更、服务进程重启 | 丢弃旧监听及会话密钥。有有效绑定、后台管理已启用、屏幕亮起且 Wi-Fi 恢复后，按当前地址恢复监听，客户端重新认证。设备重启后按同一条件恢复。 |
| 用户关闭后台管理、解除绑定或更换绑定 | 立即关闭旧连接、使旧会话失效。关闭管理保留绑定，解除或更换绑定还须撤销旧手机的重连资格。 |

配置服务在主线程接收屏幕、蓝牙状态与 Wi-Fi 变化。仅当后台授权有效、屏幕处于交互状态且有 Wi-Fi IPv4 时，服务才监听该地址。亮屏发现广播使用 Android 的 LOW_POWER 模式。配置窗口优先使用广播资源，熄屏停止管理广播并释放监听及会话。系统蓝牙可继续供音频应用使用。

前台兼容端口与后台服务有独立的密钥和生命周期。后台监听在系统通知 Wi-Fi 可用或地址变化时重建；服务进程由 Android 的 START_STICKY 机制恢复，系统启动或应用升级后按授权状态启动。空闲会话暂定 5 分钟，接入协议见 [BLE 与局域网协议](ble-provisioning.md)。目标 ROM 的实际恢复率和功耗预算需现场测量。

## 实施顺序与验收

1. **先打通手台。** 在配置 APK 内拆分 BLE 页面与 Wi-Fi 服务，用离线管理客户端和虚构配置验证应用路由、脱敏读取、写入冲突和已绑定客户端重新建会话。对讲未启动时也能保存；对讲未安装时仍能配网。
2. **再验收后台运行和功耗。** 在目标手台验证两条独立路径：客户端已连接时切到对讲，仍能读记录；手台已开始对讲时才启动测试客户端，也能连接并保存频道。核对当前轮次用旧频道完成，下一轮对讲使用新频道。覆盖断网换址、进程回收、重启与撤销绑定。用同一台手台、同一 Wi-Fi 和相同息屏时长，对照后台管理关闭、空闲监听、间歇读写三种状态，记录耗电、唤醒次数与重连成功率，再决定是否调整监听策略。
3. **最后适配微信助手。** 手台接口和后台行为验收后，小程序再接入 LAN 重连、表单和保存反馈。在真实微信上复验“手台保持对讲，打开手机拉取记录并改频道”。当前操作步骤继续见 [BLE 配网与管理协议](ble-provisioning.md)。

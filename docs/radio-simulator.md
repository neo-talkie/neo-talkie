# 手台界面模拟器

在工作区的 `neo-talkie-design-studio/` 目录运行 `npm start` 打开手台设计工作台。首页按应用展示设计稿和 Android 实图，右上角可进入交互模拟器。固件使用固定发行副本执行离线校验。

主界面只负责对话：底部下侧键显示当前频道名称，按一次切到列表中的下一项，末项回到首项；上侧创建新对话仍按上下文显隐。MENU（设备实测 DPAD_CENTER，也兼容 MENU/Enter）打开一级功能菜单，包含“网络测试、系统状态”；上下选择、MENU 进入、EXIT 从详情返回菜单，再从菜单返回对话。菜单不循环越界，不自动超时退回。上下键在对话页仅翻看长回答，其余情况不操作；音量仅由旋钮调节。NeoTalkie 的菜单、详情和自有桌面按下 PTT 立即回到对话并开始采集，松开结束；跨页重复按键/广播与快速松开由共享 PTT 状态锁处理。菜单页去掉标题，菜单项使用 18 px 字号；底部为“MENU 进入”和右对齐的“EXIT 返回”。详情页底部为像素上下小三角和“翻页”、右对齐的“EXIT 返回”。右上角仅在实际有多页时显示页码，不显示选中项序号。

`tools/simulator/` 是独立的电脑端离线 UI 评审入口，按 NeoTalkie 0.1.1 和弘讯参考照片展示机身外观、物理按键与 160×128 点阵屏。它不运行 APK，不读取设备状态，也不替代真机验收。

## 运行和交付

工作台默认地址为 <http://127.0.0.1:4176>。仅需项目已有的 Node.js，不需要 npm install、ADB 或云端凭证。端口用 `RADIO_SIM_PORT` 覆盖。默认只监听本机回环地址，静态资源限制在该应用目录，禁止写请求；CSP 限制连接到本地同源，禁止音频媒体和外部脚本/字体加载。

图片导出包括 160×128 原始 PNG、640×512 整数放大 PNG、840×1360 带机身 PNG 和 177 个命名场景的分组总览 PNG。预览像素网格不写入屏幕导出。JSON 以 `neotalkie-radio-ui/v1` 标识，导入限制类型、长度、范围；快照最多 20 个保存在本机 localStorage，可导出 JSON 留档。没有后端存储、账号、密钥、录音或语音服务调用。

## 模块职责

| 文件 | 职责 |
| --- | --- |
| `model.js` | 纯函数状态模型、预设、换行窗口、按键、音量/PTT/翻行/完成计时、快照校验。 |
| `pages.js` | 状态页、网络页、检测结果的数据模板与可调字段。 |
| `generated/ui-contract.js` | 从共享契约生成的状态、文案、布局/颜色/时间常量与完整场景；禁止手改。 |
| `scripts/` | 生成场景文档，解包浏览器导出的 PNG/参数为离线图册。 |
| `render.js` | 160×128 原生 Canvas 绘制、点阵图标、仿实物机身 SVG、最近邻缩放。 |
| `app.js` | 浏览器 DOM、快捷键、模拟时钟、参数编辑、快照和 PNG/JSON 导入导出。 |
| `server.mjs` | 无依赖的本地只读静态 HTTP 服务，路径边界与 CSP。 |
| `assets/` | 离线字体、许可证、校验和及 favicon；不包含照片、密钥、录音。 |
| `tests/` | 离线纯逻辑/本地服务/Android 布局基准检查及显式浏览器检查。 |

它与两个 Android 应用保持独立，不成为 Android 的运行依赖。字体及前端代码均随目录携带；无 CDN 请求。

## 行为基准

- 预设覆盖新对话、继续追问、采集、识别、思考、查询、合成、短/长回答、完成、音量、30 秒边界、弱信号/低电量、充电、离线/错误/空识别/说话太短，以及一级菜单、设备/网络/检测/结果、桌面和息屏。
- 预设默认冻结，便于给图。播放演示或直接操作按键使用本地模拟时钟。录音并不使用麦克风，回答均为固定示例。
- PTT 按下打断上一轮显示，电平恢复到左侧 4×25 px 竖槽。讲话时上方固定“正在听 / 松开发送”，不显示实时字幕；松手后的识别、思考和合成阶段也仅显示两行状态提示，不展示任何用户转写文字；回答正文仍可展开、上下翻看。
- 讲话时底部按上下文显示创建新对话，下侧键显示当前频道名；松手后的识别、思考/查询、合成阶段，底部 y=83–128 统一以深灰底、白字和无底槽的柔灰横条显示“思考中”，音量面板仍用原绿色，按松手后约 2.5 秒的前快后慢节奏推进，超时缓慢停留尾部，无百分比或完成宣告。开始播报后显示回答正文并恢复原底部入口/四行展开规则。
- `transcript` 与处理等待时长参数、编辑框和 JSON 快照保存模拟用户识别文字；转写仅为内部模拟数据，用于验证不会出现在屏幕上，不采集真实音频。
- 松开时不超过一秒显示“说话太短 / 请重新说话”，1.5 秒后就绪；正常时长继续模拟识别、思考、合成和播报。真实应用仍从开始连接并流式发送 ASR，短录音结束才取消，不增加预缓存。
- 运行时始终保持 20 px 大字，系统提示固定两行，实际回答正文超过两行时，仅创建新对话/当前频道文字在 100 ms 内淡出，文本扩展到最多四行；无缩字号、无省略号，超四行用上下键逐行翻看。左侧圆形图标始终保留；已有回答正文时隐藏状态行，正文直接从第一行开始，合成/播放/播后保留阶段一致。文字变短或展示结束后，底部提示淡入恢复。
- 对讲页按 EXIT 收起回答、提示或音量条，正在进行的对讲随之停止。返回“按住PTT说话”后再按 EXIT 退出，已有追问上下文保留。
- 完成保留三秒；用户翻行取消该倒计时，每次按键续五秒。若五秒时回答仍在进行，退出翻看回首屏；已完成则回大字待机。不会截断模拟中的回答。
- 音量使用 0–5 档、两行 y=83–128 横条、1.6 秒消失。旋钮直接表达最终用户方向，不向真实设备发送按键。
- 一级 MENU 菜单、上下选择/MENU 进入、EXIT 逐层返回及 PTT 回到对话与原生一致。厂家系统界面仍是模拟边界。

## 像素精度与维护

所有文字先以 14/16/20 px 字号栅格化进 160×128 Canvas，再整数倍放大，避免高分辨率 CSS 文字冒充低分屏。点阵数字、Wi-Fi 未点亮灰色弧线、白色电池及充电闪电、青绿色 PTT 和圆形侧键采用源码坐标。机身视图会随窗口缩放，精确像素检查用屏幕视图/原始 PNG。

内置开源字体提供稳定跨电脑结果；支持当前会话载入设备字体。由于厂家字体、Android 与浏览器字体渲染和液晶色偏不同，尚不保证与 ROM 截图逐像素一致；机身是参考照片的示意重绘。来源见 [THIRD_PARTY](../tools/simulator/THIRD_PARTY.md)。

修改 UI 时先更新 `config/radio-ui/` 共享定义并生成两端配置；适配代码变更需更新有截图依据的复核记录，详见 [UI 一致性机制](radio-ui-contract.md)。`tests/server.test.mjs` 对当前 Android 版本、主区域坐标、四行大字基线、音量范围与时限建立变更检查，提示维护者重新对齐。

## 验证

`npm --prefix tools run simulator:test`：40 项 Node 检查，覆盖状态转换、翻行和计时边界、Unicode、原档位音量、快照输入、静态服务以及 Android 布局基准。`tests/browser-check.js` 在本地页面执行完整浏览器检查（当前按浏览器报告计数，含 177 个场景逐一渲染），验证实际绘制、交互、五秒恢复、像素整数缩放和三种图像生成；通过 resource entries 核对运行中仅请求本地资源。没有外部服务测试，也没有接触手台。

当前评审产物位于 `data/ui-regression/latest/`（不提交生成产物）：`index.html` 展示全量图册，`visual-diff.html` 对比 Git 基准和当前画面，`visual-diff.json` 保存场景、检查结果与源码指纹。过渡中间帧使用与交互预览相同的画笔透明度；100 ms 计时通过纯函数检查，不以静态截图证明帧率。

0.2.16 回答正文顶格对比及真机检查截图见 `data/android/qa/ui-0.2.16/`，`preview.png` 对比尚无回答、开始显示正文及播后保留三个阶段。

0.2.17 同步两行系统提示、同宽 PTT 竖线、正文展开保留圆形图标和充电状态；22 项离线检查与 49 项浏览器检查通过。四状态预览及对应真机截图见 `data/android/qa/ui-0.2.17/`。

0.2.18 同步底部连续讲话电平、固定 PTT 图形、松手隐藏及短录音提示；23 项离线测试、52 项浏览器检查通过。最新预览和真机 UI 诊断截图见 `data/android/qa/ui-0.2.18/`。

0.2.20 合并上方用户文字、PTT 竖向电平和前快后慢的等待进度。25 项离线测试、57 项浏览器检查通过；最新预览及真机 UI 截图位于 `data/android/qa/ui-0.2.20/`。

0.2.21 讲话期间隐藏进度面板，等待阶段标题统一“思考中”；25 项离线测试、59 项浏览器检查通过，预览和真机 UI 截图见 `data/android/qa/ui-0.2.21/`。

0.2.26：待机按上下文显示“新对话 / 继续追问”；“创建新对话”图标和文案只在有上下文时出现，上侧键清空模拟上下文。提供上下文开关和预设，五分钟到期恢复新对话。

0.2.28 电平显示基准：Android 使用去直流偏置的 RMS 和 64～32768 对数映射；模拟器的 `level` 仍是映射后的 0～100 显示值，用于检查空、半高、满格样式，不分析或采集音频。


## 全量回归覆盖与参数

[场景清单](radio-simulator-states.md)与导出的总览编号一致。覆盖当前 NeoTalkie 自有的对话、状态诊断、桌面三类界面及息屏示意；数值的无限组合通过参数编辑复现。厂家系统设置、系统授权弹窗、其他 APK 界面不在范围内，桌面外部应用图标使用问号占位，点击后明确提示进入模拟边界。息屏/唤醒只模拟界面切换，不能复现硬件休眠故障。

常用参数直接编辑；“完整状态参数”先读取当前 JSON，修改后应用并冻结。`view` 选择页面；`page`、`selected`、`offset` 从 0 开始，表单页码和选中项从 1 开始。`device` 编辑型号、版本、供电、温度、内存、存储、运行时长、配置是否加载；`network` 编辑 wifi/mobile/other/offline、SSID、IP、网关、RSSI、链路、频率；`results` 是最多三项的 name/success/message/detail/elapsedMs 数组，空数组展示无结果；`checking` 选择正在检测的服务。`homeLabels` 编辑桌面应用列表；`footerOpacity` 为 null 时正常演示，0～1 可冻结淡出中间帧。`battery=-1` 表示未知电量。

预设不触发检测。点击本地演示时服务检查按所选服务播放合成结果，返回取消。所有数据保留在当前浏览器内，只有主动保存快照才写 localStorage。

单状态格式继续使用 `neotalkie-radio-ui/v1`；全量清单使用 `neotalkie-radio-regression/v1`，每条记录包含编号、稳定 ID、名称、分组、说明及完整单状态快照。总览 PNG 直接使用相同渲染函数和冻结参数，原屏像素按 2× 放大，编号与清单一一对应。

回归步骤：运行 Node 检查 → 在本地页面执行 `tests/browser-check.js` → 检查状态总览 → 导出 PNG 与全量参数。需要独立截图时，在页面执行 `tests/export-gallery.js` 并保存返回 JSON，再用 `scripts/unpack-gallery.py` 生成离线 HTML、每个状态的原始 PNG 和可导入参数。生成物放 `data/`，不入 Git；场景目录变化后运行 `scripts/catalog.mjs` 更新此版本的清单。新增原生允许状态必须有共享场景，生成漂移、两端行为对照和适配源码复核记录均已接入 CI。统一入口为 `make ui-check` 与 `make ui-visual`；详见 [UI 一致性机制](radio-ui-contract.md)。


### 闲置息屏回归

0.2.36 起与安卓共享 `IDLE_SCREEN_MS=40000`。启用时间推进后，空闲页面 40 秒未操作进入息屏；
录音、处理、播报及正在运行的检测保持显示，结束后重新计时。PTT 从 NeoTalkie 息屏页直接回到主界面并进入录音，
外部应用息屏不被模拟器接管。这里只模拟显示/交互状态，实际功耗、系统后台生存和硬件唤醒必须真机验收。

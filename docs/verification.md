日期：2026-11-24。当前为独立设备仓库的开发版本，采用 Apache-2.0。

- 桌面和对讲两个 APK 分别构建，并通过 APK 签名验证；两包使用同一本地开发签名，包名不同。
- 238 项已有 Java 离线检查，以及 10 项跨应用 PTT 令牌生命周期检查。
- 40 项模拟器测试，1,307 组 Java/JavaScript 行为对照。
- 151 个 UI 场景、226 项浏览器检查，固定场景两次渲染一致；检查了新品牌桌面、桌面设置、网络/系统状态的图册。截图为模拟器画面。
- 公开文件清单检查：不含服务器模块、私有配置、签名、录音、本机绝对路径或旧产品标识；本地构建工具、APK 和 QR 位于忽略目录。该检查是针对迁移清单的静态检查，不替代公开发行前的代码审阅。

## NeoTalkie Audio Link（音频互联）

2026-11-26，mx_b5（MSM8909，Android 5.1.1，LMY47V，2023-12-13 构建）与 macOS 14.4 完成 HFP 麦克风实测。

1. 在已授权的 USB ADB 会话中，使用实际设备序列号执行 `adb -s "$SERIAL" shell setprop persist.service.bt.hfp.client true`。用独立的 `adb -s "$SERIAL" shell getprop persist.service.bt.hfp.client` 确认返回 `true`。本机原值为空，普通 shell（UID 2000，SELinux Permissive）即可写入。本机普通应用的写入实测见下文。
2. 在手台系统蓝牙设置关闭蓝牙，等到关闭后重新开启。蓝牙日志出现 `isHfpClientEnabled = true` 和 `HeadsetClientService` 启动记录。此 ROM 在该角色下执行 `dumpsys bluetooth_manager` 打印配置列表时曾抛出空指针异常，可通过 `dumpsys activity services com.android.bluetooth`、蓝牙日志和电脑端的 HFP 服务识别结果交叉确认。
3. 在 Mac 蓝牙设置中选择目标手台，核对双方配对码后连接。Mac 枚举出蓝牙输入、输出端点，输入为单声道、16 kHz。本次配对后，Mac 自动将默认输入和输出都切换到了手台。
4. 将采集端绑定到手台的 Core Audio 输入端点，测试音单独从 Mac Studio 内置扬声器播放。依次播放 1,000 Hz 和 1,500 Hz，只在内存中统计 16 位 PCM 的频率分量。手台日志显示宽带 SCO 开启，`start_hfp` 返回 0，状态进入 `AudioOn`。

| 声源 | 输入中的 1,000 Hz 分量峰值 | 输入中的 1,500 Hz 分量峰值 |
| --- | ---: | ---: |
| 播放前基线 | 11 | 3 |
| 播放 1,000 Hz | 5,549 | 69 |
| 播放 1,500 Hz | 41 | 1,754 |

以上验证了从物理声源经手台麦克风到 Mac 的实时音频通路。Windows 兼容性、重启重连和现有对讲 PTT 与麦克风模式的切换仍待单独验收。恢复原蓝牙角色时，用相同 ADB 会话将该属性设为 `false`，再关闭并重新开启手台蓝牙。原厂代码在属性为空时同样按 `false` 处理。

### 从普通 APK 启用

在同一台手台安装当时名为「蓝牙麦克风」的独立 APK（现名「音频互联」）。初版安装包声明普通蓝牙访问和蓝牙管理权限，带 PTT 门控的版本另声明普通音频设置权限。按「恢复原模式」后读回属性为 `false`，蓝牙服务日志也读到 `false`。从 NeoTalkie 桌面选中「蓝牙麦克风」并按确认键，应用自动将属性写为 `true`，蓝牙服务启动 `HeadsetClientService`。两次切换均由应用自己的 UID 执行。

Mac 保留了已有配对，本次切换后在电脑上点「连接」恢复了 16 kHz 单声道输入。电脑内置扬声器依次播放 1,000 Hz 和 1,500 Hz，从手台输入分别测得对应频率幅值 4,239 和 1,650，播放前基线分别为 11 和 6。退出应用后再次从桌面打开，蓝牙服务进程和电脑输入端点均保持在线。若连接新电脑，通过应用中的「蓝牙配对」打开系统蓝牙设置并核对两端配对码。此项验证覆盖 mx_b5 当前 ROM，其他固件的系统属性访问策略可能不同。

### 在同一连接上触发 Mac Fn 并收音

mx_b5 保持 HFP 模式，普通「Fn 实验」APK 通过出厂 HID Device 接口注册键盘，报告使用 Consumer 页 0x0C 的 Globe 键 0x029D。Mac 在蓝牙设置中断开并重新连接手台，保留原配对。macOS 14.4 随后同时列出 HFP 与 HID，系统 HID 列表出现该手台的蓝牙键盘。实验期间 Typeless 已退出。

- 通过手台实验 APK 的屏幕按钮发送一次按下和松开，Mac 检测到系统 Fn 修饰键的两次状态变化。在持续采集手台音频的同时，这次按键也被识别。
- 单独验证先按键再收音。Mac 上的测试程序等到系统 Fn 按下事件后才打开手台音频输入。手台进入 AudioOn，Mac 在单声道 16 kHz 输入里分别测得 1,000 Hz 和 1,500 Hz 测试音，对应频率幅值为 703 和 53，基线为 4 和 5。
- 手台端按住约 2.02 秒时，Mac 的 Fn 修饰键状态持续约 0.16 秒。此编码已验证单次触发。这次实验用了独立测试包。麦克风 APK 的两种 PTT 模式见下节。

### 普通 PTT 与 Fn 首尾点按

在 mx_b5 与同一台 macOS 14.4 电脑上关闭 Typeless，以手台厂商 PTT 广播驱动应用。电脑持续读取手台的 16 kHz 单声道输入，并从内置扬声器播放 1 kHz 测试音。下列结果来自实际蓝牙输入和系统 Fn 状态，未保存语音。

- 普通 PTT 在按键前的 119 个音频块和松手后的 66 个块全部为零，讲话窗口的测试音幅值达 679。单用 Android 的麦克风静音开关仍能听到测试音，当前实现改用厂商 HFP 音频通路。
- 首尾点按每次发出 220 毫秒的按下报告。首次 Fn 松开后，应用等待 500 毫秒才请求打开通路。一轮测量中，Mac 首次检测到 Fn 松开至收到有效音频约 0.77 秒，最后一个有效音频块之后约 0.25 秒检测到第二次 Fn 按下。

另一次 55 秒待机采样中，Mac 上偶见峰值至 13/32768 的微小非零采样；PTT 关闭的是手台的语音通路，电脑仍保留蓝牙输入端点。

0.3 覆盖安装到此前选择长按模式的手台后，应用自动回到普通 PTT，菜单只有「普通 PTT」和「Fn 首尾点按」。在 Mac 读回手台键盘映射为空后重测，普通 PTT 传入音频且未检测到 Fn，首尾点按在 Mac 上各产生一次 Fn 按下与释放。验证由设备的 PTT 广播触发，期间 Typeless 已退出。

### 音频互联 0.4

在同一台 mx_b5 上以原签名覆盖安装。桌面入口显示「音频互联」，首页能完整显示本机蓝牙名称、电脑输入提示和四个操作按钮。已逐页查看使用指南，并从配对按钮进入系统蓝牙设置后返回。通过手台导航键码选择 Fn 模式，再通过厂商 PTT 广播触发收发。Mac 在默认按键配置下检测到首尾两次 Fn 点按和期间的手台音频。普通 PTT 收音时未检测到 Fn。电脑可枚举同名通话输出，扬声器实际发声仍待现场验收。

### 音频互联 0.5

在 mx_b5 上覆盖安装后，仅用上下键码（F7/F8）和确定键码（DPAD_CENTER/ENTER）走通两种模式的选择和蓝牙配对确认。160×128 首页和模式页均使用单列选择，当前焦点可见。配对允许后返回音频互联，HFP 角色仍开启。

分别在首页按返回、按 HOME、切换至「NeoTalkie对讲」，以及在系统配对弹窗按 HOME。每种离开路径都读回 `persist.service.bt.hfp.client=false`，并确认 `PttService` 已结束。快速回桌面再打开时读回 `true`，再次退出后读回 `false`。验证结束时保留普通 PTT，手台处于原蓝牙角色。

### 音频互联 0.6

在同一台 mx_b5 上覆盖安装 0.6。打开应用后，两个厂商属性均读回 `true`，蓝牙进程同时启动 `A2dpSinkService` 和 `HeadsetClientService`。Mac 的旧配对初次自动连接时只有键盘可用。在 Mac 蓝牙设置中断开手台并再次连接后，服务发现同时返回 Audio Sink（0x110B）、Hands-Free（0x111E）和 HID（0x1124），配对记录得以保留。

- Mac 同时列出 44.1 kHz 双声道输出和 16 kHz 单声道输入。PTT 松开时，从 Mac 播放 1 kHz 测试音，手台记录到 A2DP 播放开始、取得音频焦点、硬件输出选择内置扬声器，播放完成后进入暂停。
- 打开 Mac 的手台麦克风输入时，手台进入 HFP AudioOn。首次收音复测期间，原先休眠的对讲页被 PTT 广播唤回，测试窗口未收到有效信号。使用 0.6 验证麦克风实收与切回媒体播放时，应从亮屏的音频互联首页开始。
- 实测离开应用后 HFP 属性恢复为原来的 `false`，A2DP 属性读回原来的空值。媒体音量与扬声器实际出声、iPhone 输出选择均需现场确认。
